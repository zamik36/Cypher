## Этапы 0–5: что сделано

- **Этапы 0–3.** Интеграционный прогон против реальных NATS и Redis, в том числе на двух репликах gateway, идёт в CI (job `e2e`). Права NATS выданы по принципу наименьших привилегий (`deploy/nats.conf`). Старые крейты удалены.
- **Этап 4.** `cypher-client` — tokio-драйвер вокруг `cypher-core`: SQLite в отдельном потоке, авто-переподключение, onion-канал, Tor через arti с мостами. Десктоп переведён на него, живой сценарий двух нативных клиентов идёт в CI.
- **Этап 5.**
  - `cypher-wasm`: ядро работает в Web Worker. Сид не покидает память WebAssembly. Состояние хранится в IndexedDB (строгая durability, запись до отправки), входящие файлы — в OPFS, исходящие файлы — в IndexedDB, поэтому передачу можно возобновить после перезагрузки.
  - Фронтенд вынесен в `packages/ui` и работает через интерфейс `Platform`: Tauri на десктопе, Worker RPC в браузере. Дублирование между приложениями устранено.
  - Строгий CSP (`script-src 'self' 'wasm-unsafe-eval'`, `connect-src 'self'`) задан заголовком в Caddy и meta-тегом. Gateway доступен по `/ws`, relay — по `/relay`.
  - Проверка:
    - `apps/pwa/scripts/live.mjs` в CI: два WASM-клиента через WebSocket проходят ссылку, переписку и офлайн-доставку через onion-inbox;
    - ручной прогон в Chrome на настоящем Worker: идентичность, ссылка и QR, чат, файл 3 МБ со сверкой SHA-256, перезагрузка с восстановлением истории, офлайн-сообщение, экспорт мнемоники, отказ на неверный пароль.

## Этап 6. Голосовые сообщения и видео-«кружочки» — сделано

- **Голос нативно.** Крейт `cypher-media`:
  - захват через cpal в отдельном потоке, lock-free SPSC-кольцо без аллокаций в аудио-колбэке;
  - ресемплинг в 48 кГц, Opus 24 кбит/с (VOIP), свой WebM-мультиплексор с Duration и Cues;
  - волна из 64 столбцов и индикатор уровня.

  Opus — эталонная C-библиотека libopus через крейт `opus` (собирается cmake, на Android — тулчейном NDK). Трансляция на Rust (`unsafe-libopus`) убрана: Miri нашёл в ней UB. В воркспейсе теперь нет `unsafe` (`unsafe_code = "forbid"`). В браузере голос кодирует `MediaRecorder`.
- **Кружочки.** Общий для WebView и браузера рекордер:
  - квадрат 384×384 через canvas;
  - VP9/VP8/H.264 — что поддерживает платформа;
  - до 60 с, JPEG-постер ≤ 16 КБ.

  В Rust передаётся одним бинарным IPC-телом, без base64.
- **Хранение и воспроизведение.**
  - Ключ файла сохраняется в таблице `media` (запечатан Vault); файл лежит на диске в виде зашифрованных чанков.
  - Десктоп: протокол `cypher-media://` с Range расшифровывает только нужные чанки.
  - PWA: расшифровка в Worker и blob URL.
- **UI.**
  - Удержание — запись, короткое нажатие — переключение голос/видео, свайп влево — отмена, Esc — отмена.
  - Пузырь голосового: волна с прогрессом, перемотка, скорость 1×/1,5×/2×.
  - Круглое видео: кольцо прогресса воспроизведения и загрузки.
- **Разрешения.**
  - CSP `media-src` для обеих платформ.
  - macOS: `Info.plist` и entitlements.
  - Android: `RECORD_AUDIO`/`CAMERA`.
  - Linux: разрешение getUserMedia в WebKitGTK.
- **Найдена и исправлена ошибка.** Нативный драйвер читал исходящее медиа из недописанной зашифрованной копии: получатель получал валидный файл из нулей. Живой тест теперь сравнивает расшифрованное содержимое с оригиналом.
- **Проверка.**
  - Юнит-тесты: WebM разбирается независимым демультиплексором, работает поиск по Cues, голосовой конвейер кодирует 100 кадров за 2 с, ресемплер проверен.
  - Сценарии ядра: чанковое и inline-медиа воспроизводятся у обеих сторон, отмена удаляет ключ.
  - Живой тест нативного клиента: голосовое и видео 300 КБ через Range-чтение.
  - Headless Chrome с фейковыми устройствами: голосовое записывается, доставляется и проигрывается; кружочек декодируется в кадр 384×384; удержание кнопки в реальном UI доставляет голосовое.
- **Открыто.** Проверка на реальных устройствах macOS и Android; проигрывание входящего медиа до окончания загрузки (Range уже поддерживается, UI пока ждёт завершения).

- 100 000 соединений на узел;

## Проверка (сквозные пользовательские сценарии)

1. Первый запуск: создание, разблокировка и импорт идентичности.
2. Ссылка/QR; вход по ней, в том числе по неверной или просроченной ссылке — должна быть ошибка, а не зависание.
3. Первое сообщение с обеих сторон.
4. Офлайн-сообщение через inbox, доставка после входа.
5. Файл 1 ГБ: передача, обрыв, возобновление, проверка целостности.
6. Голосовое: запись, отмена, отправка, воспроизведение с волной.
7. Кружочек: запись, отправка, воспроизведение до окончания загрузки.
8. Обрыв сети → авто-переподключение → досылка из очереди.
9. Режим Tor и onion, получение inbox через relay.
